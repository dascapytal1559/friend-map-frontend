# The demo

The demo is friend-map's map views on a made-up crowd, for showing friend-map off: Orbits, Orbits 3D, the Spider web, the City, the river and Reciprocity, with the Query bar, Methodology and the person panel, read only. It is the same pages in two places: at `/demo` in the app (see "The demo" under Orbits in [The views](views.md)), and as the **static demo**, plain files with no server behind them, for a site of their own (see [Going live on Cloudflare Pages](#going-live-on-cloudflare-pages)). `npm run build:demo` builds the static demo into `dist-demo/` (gitignored) from `src/demo/index.html` and its entry, `src/demo/main.tsx` (`vite.demo.config.ts`, whose mode, `static-demo`, is what tells the page it is the static demo: `staticDemo` in `src/demoMode.ts`), with its views at the root of the site (`/`, `/orbits-3d`, `/spider`, `/city`, `/river`, `/reciprocity`). Its settings start at your saved view settings (see [Saved view settings](settings.md#saved-view-settings)) as they are when it is built: the build reads `view-settings.json` from the data folder, found as `check-demo` finds it (in a worktree, through git config), puts in only those settings, each one of its own values, and says which it carried; so the next build and deploy carry your Spider web as you last set it, and nothing else of the data folder goes in. Every view and panel reaches the archive through one interface, `ArchiveApi` in `src/archiveApi.ts`, which the app's entry (`src/main.tsx`) points at the server's routes (`src/archiveHttp.ts`) and the demo at data held in the page (`src/demo/archive.ts`, which answers as the server's read paths do, with its own copies of the archive's rules, name checks and query language, `src/demo/rules.ts` and `src/demo/query.ts`, which the demo parity test holds to the archive's), so the demo is the app's views over another source, not a copy of them. It is read only: the demo's archive refuses every write, saying so, and the person panel shows its name, aliases, tags, location, note, reaching out and accounts as text, with nothing to change them (`src/readOnly.ts`). There is no Table, Calendar, Circles, composer, Changes, tag or value manager, Names, usage record or live reload, and nothing in its switcher is called frozen; the static demo's files hold neither the server's routes nor the Table's or the Calendar's code (the app's entry gives those pages to the page, `OwnPages` in `src/demos/Demos.tsx`, and the static demo's gives none). The Query bar's box, with no model behind a static page, offers example requests instead (`src/demo/examples.ts`; `examples` on `QueryBar`), each with the query it becomes: picking one puts its words in the box and runs its query, and Methodology says so.

The crowd (`src/demo/generate.ts`, every word of it from `src/demo/words.ts`) is shaped like the real map at about half its size: 400 people on the map (`DEMO_SIZE`; the real map had 814 when the numbers were last taken), and everything else in the same proportion to it, so as many archived by hand and by each archive rule in proportion (about 10,000 in all, most of them met only in big group chats), as many group chats in proportion (361), as big and as busy, about as many messages in proportion (about 720,000, from 2009 on), calls (answered and missed, with about as many people) and hangouts, and the same platform mix, tags per person, locations, people to reach out to, reactions and chats picked up again after a quiet spell, each friendship talked in some months and not others, a few days at a time. Its closeness, scored as Orbits scores it, falls in each band from the belt to the sun much as the real map's does, so its rings fill and its layout looks much like it. Every name, tag, place, title and line of chat is invented, and group chats' titles start with a made-up place, so none is any real chat's. Names are made in full, one person to each, and the demo shows them as a first name and the first letter of the last with a full stop ("Ada S."; `shortened` in `src/names.ts`): people, aliases and accounts alike, everywhere off the map whatever its Names, and on the map to start with; its Names (kept in the browser apart from the real app's) offers First name, First L., Full name and No name for the map, but not No name except…, since nobody in it is real. A one-word name, an address and a deleted account's placeholder stay as they are, and the people on the map are named first, so no two of them share a short name. The frozen views draw the names as they are kept, in full. The crowd is made in the page as it opens by a seeded generator (about an eighth of a second, and as long again for its archive to add it up, on a recent Mac), so the same day gives the same crowd and nothing made up is stored anywhere. Its messages are columns of numbers (`DemoMessages`: which chat, who, when; about 10 MB in the page), not objects, and none of them keeps its line of chat: `messageText` picks it from a modest pool of made-up lines by where the message is, when a chat is shown, so the same message always reads the same, and the pool (`everyLine`) is all there is to check. It is shaped by numbers taken from the real map with `npm run demo-shape` (`server/demo-shape.ts`, from the facts the archive's server gives, `GET /api/archive/map-facts`, and its score report, closeness scored with friend-map's own scoring): how many people are shown and archived by which rule, messages per person, who writes more, when people were last and first spoken to, the platform mix, group chats' sizes, titles, people on the map in each, busyness and age, tags per person, location, reaching out, closeness (with hangouts and calls, as the map scores it), calls (answered and missed, how many people, how many each, how long, and when) and hangouts (how many, over how many days, how many people at each, how long), and activity by month, as counts and distributions only (`DemoShape` in `src/demo/shape.ts`), written to `src/demo/mapShape.ts`, which is checked in and never holds a name, a title, a handle, an id or a message. A test's crowd is the same kind of crowd at a smaller size (`SMALL_CROWD`: 80 people on the map).

Tests: `src/demo/generate.test.ts` (the crowd is the same every time; `DEMO_SIZE` people on the map and as many archived by each rule as the real map in proportion, as many group chats in proportion as big, closeness's share in each band within a fifth of the real map's, about as many messages, people called and hangouts in proportion; each chat's messages together and in order, each reading as a line of chat; names kept in full, one person to each and no two on the map to a short one, sharing no word with the made-up crowd of the map views; and, where your archive is on this machine, at `data/` or `FRIEND_MAP_DATA`, no name, alias, handle or group chat title from it in the crowd and no real name of two words or more in any line of chat it can hold, a check that says only how many it found and is skipped where there is no archive), the life archive's `server/archive/demoParity.test.ts` (the demo's archive beside the server's over a small crowd, its names in full (the archive joins accounts by name), imported into a temporary archive through the connectors' events, calls included, and your edits: the same people archived for the same reasons with the same counts, the same map report with its hangouts and days of calls, hangouts and calls listed, group chats, answers to a query and pages of messages, no Table or Calendar to answer for, and every write refused; and the demo's copies of the archive's rules, name checks and query language answering as the archive's do, case by case), `src/demo/examples.test.ts`, `src/demoMode.test.ts` (the demo at `/demo`: its views' addresses under it and no Table, Calendar or Circles, chosen by the address alone with the old switch's stored choice cleared, every archive call answered in the page with no request to the server, only the known files reaching the network, the static demo's page the same app on the crowd with its network shut, and each of its views and Methodology drawing the crowd), `src/views.test.ts` and `src/viewSwitcher.test.ts` (the demo's views and switcher, under `/demo` and at the root), `src/readOnly.test.ts`, `server/check-demo.test.ts` (the check on the built files, over made-up ones), the life archive's `server/archive/mapFacts.test.ts` (the archive's facts over the made-up crowd's archive with a call and a hangout added: the app's counts, and nothing but counts, times and ids) and `server/demo-shape.test.ts` (the shape from made-up facts: every distribution, closeness scored as the map scores it, and nothing but counts).

To see it: `npm run build:demo`, then `npm run preview:demo` serves `dist-demo/` at http://localhost:4173 (Vite's preview, which reads neither `_headers` nor `_redirects`; the page's own policy holds there too).

## Going live on Cloudflare Pages

The static demo is a site of its own on Cloudflare Pages, deployed by hand as the plain files `dist-demo/` holds (about 760 kB, 250 kB gzipped, when this was written): no build runs on Cloudflare and no server is behind them, and nothing deploys it automatically. Beside the files, `src/demo/public/` holds what Pages reads, which the build copies in: `_headers` (no framing by another site, no guessing at file types, no referrer, none of the browser's devices, and a year's caching for the hashed scripts and styles under `/assets/`) and `_redirects` (the app's addresses for the demo, `/demo` and `/demo/<view>`, lead to the same views at the root). Pages serves `index.html` for any other address (there is no `404.html`), and the page shows the view the address names, or Orbits. The page's own policy (`index.html`) lets it load only its own files and reach no network at all.

Every time:

1. `npm run build:demo`
2. `npm run check-demo` holds `dist-demo/` to what may be published (`server/check-demo.ts`): no file in it is any file of the data folder or the archive's, byte for byte, whatever it is called, but for this repository's own copies in a git repository kept there (a clone of this repository), which it notes: a file this repository has committed, and the same file at the same path of that clone's earlier `dist-demo/`, while every other file in such a clone, and everything outside one, is compared as before; nothing but what a page is made of; no server route (`/api/`); and no private data, by the life archive's privacy guard (one `npm --prefix <life archive> run guard -- scan --json <files>` over the built files and the app's own code, which says where and which rule, never what; see [Keeping private data out of commits](wiring.md#keeping-private-data-out-of-commits)), reading lists the minifier joined with dots word by word, except what the app's own code or the libraries it is built from have too (an ordinary word there, which it notes). The life archive is `LIFE_ARCHIVE_HOME` (from the environment or `.env.local`), else `~/Projects/life-archive`; with none there, or a guard that cannot answer, nothing may be published. The folders are `--data <dir>` alone, else (git config `friendmap.dataDir` and `friendmap.archiveDir`, else `FRIEND_MAP_DATA` and `FRIEND_MAP_ARCHIVE_FOLDER`, else `data/`; see [Running](running.md) and [The data folder](running.md#the-data-folder)); in a worktree without your data, set those two git configs, or pass `--data` with your data folder (which then misses your archive's). It prints every file with its size, raw and gzipped, then how many of which rule it found in which file, never what, and exits 1 when anything may not be published.
3. `npx wrangler pages deploy dist-demo --project-name <project> --branch main` publishes them. The first time, log in (`npx wrangler login`) and make the Pages project (`npx wrangler pages project create <project> --production-branch main`, or in Cloudflare's dashboard as a project uploaded directly). The demo is then at `https://<project>.pages.dev/`, and each deploy after replaces it (Pages keeps the earlier ones, to roll back to).
